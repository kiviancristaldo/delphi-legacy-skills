# Firebird → PostgreSQL

## Tipos de dados
| Firebird | PostgreSQL | Atenção |
|---|---|---|
| `SMALLINT`, `INTEGER`, `BIGINT` | `smallint`, `integer`, `bigint` | |
| `NUMERIC(p,s)`, `DECIMAL(p,s)` | `numeric(p,s)` | |
| `FLOAT` | `real` | |
| `DOUBLE PRECISION` | `double precision` | |
| `CHAR(n)`, `VARCHAR(n)` | `char(n)`, `varchar(n)` | banco PG em UTF8: converta o charset dos dados (WIN1252/ISO8859_1) na carga |
| `BLOB SUB_TYPE 1` / `BLOB SUB_TYPE TEXT` | `text` | |
| `BLOB SUB_TYPE 0` / `BLOB` | `bytea` | |
| `DATE` (dialeto 3) | `date` | |
| `DATE` (**dialeto 1**) | `timestamp` | no dialeto 1 o DATE tem hora |
| `TIME` | `time` | |
| `TIMESTAMP` | `timestamp` (sem fuso) | |
| `BOOLEAN` (FB 3+) | `boolean` | |
| `CHAR(1)` 'S'/'N', `SMALLINT` 0/1 usados como booleano | manter, ou `boolean` | trocar muda o Delphi (TBooleanField): decida com o usuário |
| Domínio (`CREATE DOMAIN`) | `CREATE DOMAIN` | o PG também tem domínios |
| `COMPUTED BY (expr)` | `GENERATED ALWAYS AS (expr) STORED` (PG 12+) | a expressão precisa ser imutável; senão, view ou trigger |

## Identificadores
- Firebird guarda nomes sem aspas em **MAIÚSCULAS**. O PostgreSQL converte para **minúsculas**.
- Crie tudo **sem aspas** no PG. Se o script do Firebird tiver `"NOME"` com aspas, remova as
  aspas: senão a coluna fica eternamente maiúscula e exige aspas em todo SQL.
- Confira palavras reservadas do PG usadas como nome de coluna (`user`, `order`, `limit`,
  `offset`, `desc`, `end`...): renomeie ou use aspas, decidindo com o usuário.

## Generators
| Firebird | PostgreSQL |
|---|---|
| `CREATE GENERATOR GEN_X;` / `CREATE SEQUENCE GEN_X;` | `CREATE SEQUENCE gen_x;` |
| `GEN_ID(GEN_X, 1)` | `nextval('gen_x')` |
| `NEXT VALUE FOR GEN_X` | `nextval('gen_x')` |
| `GEN_ID(GEN_X, 0)` (valor atual) | `currval('gen_x')` só na mesma sessão; para ler o último valor: `SELECT last_value FROM gen_x` |
| `SET GENERATOR GEN_X TO 100;` | `SELECT setval('gen_x', 100);` |
| `SELECT GEN_ID(GEN_X,1) FROM RDB$DATABASE` | `SELECT nextval('gen_x')` |
| Coluna `GENERATED BY DEFAULT AS IDENTITY` (FB 3+) | igual |

**Trigger de autoincremento** (padrão clássico do Firebird):
```sql
CREATE TRIGGER CLIENTES_BI FOR CLIENTES ACTIVE BEFORE INSERT POSITION 0 AS
BEGIN
  IF (NEW.ID IS NULL) THEN NEW.ID = GEN_ID(GEN_CLIENTES_ID, 1);
END
```
No PG, a trigger não é necessária:
```sql
-- opção A: o Delphi não lê o generator diretamente
id integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY
-- opção B: o Delphi lê o generator (GEN_ID no código, UpdateOptions.GeneratorName): mantém o nome
CREATE SEQUENCE gen_clientes_id;
id integer DEFAULT nextval('gen_clientes_id') PRIMARY KEY
```
Depois da carga dos dados, ressincronize:
```sql
SELECT setval(pg_get_serial_sequence('clientes', 'id'), (SELECT COALESCE(MAX(id), 1) FROM clientes));  -- identity
SELECT setval('gen_clientes_id', (SELECT COALESCE(MAX(id), 1) FROM clientes));                         -- sequence
```

## Triggers
O PG separa a função da trigger:
```sql
-- Firebird
CREATE TRIGGER CLIENTES_BU FOR CLIENTES ACTIVE BEFORE UPDATE POSITION 0 AS
BEGIN
  NEW.DATA_ALTERACAO = CURRENT_TIMESTAMP;
END

-- PostgreSQL
CREATE OR REPLACE FUNCTION clientes_bu() RETURNS trigger AS $$
BEGIN
  NEW.data_alteracao := CURRENT_TIMESTAMP;
  RETURN NEW;                      -- obrigatório em BEFORE (RETURN NULL cancela a linha)
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER clientes_bu BEFORE UPDATE ON clientes
FOR EACH ROW EXECUTE FUNCTION clientes_bu();   -- PG 10 ou anterior: EXECUTE PROCEDURE
```
| Firebird | PostgreSQL |
|---|---|
| `NEW.X = valor` | `NEW.x := valor` |
| `INSERTING`, `UPDATING`, `DELETING` | `TG_OP = 'INSERT'`, `'UPDATE'`, `'DELETE'` |
| `BEFORE INSERT OR UPDATE` | igual, com `TG_OP` para distinguir |
| `POSITION n` (ordem) | o PG dispara em **ordem alfabética do nome**: nomeie `t01_...`, `t02_...` |
| `ACTIVE`/`INACTIVE` | `ALTER TABLE t ENABLE/DISABLE TRIGGER nome` |
| `EXCEPTION E_NOME;` | `RAISE EXCEPTION 'mensagem';` |
| `AFTER DELETE` com `OLD` | `RETURN OLD;` (ou `NULL` em AFTER) |

## Stored procedures
**Selecionável** (tem `SUSPEND`, chamada com `SELECT * FROM proc(...)`) → função que retorna tabela.
A chamada no Delphi **continua igual**: `SELECT * FROM vendas_por_cliente(:ano)`.
```sql
-- Firebird
CREATE PROCEDURE VENDAS_POR_CLIENTE (ANO INTEGER)
RETURNS (CLIENTE_ID INTEGER, TOTAL NUMERIC(15,2)) AS
BEGIN
  FOR SELECT CLIENTE_ID, SUM(VALOR) FROM VENDAS
      WHERE EXTRACT(YEAR FROM DATA) = :ANO GROUP BY CLIENTE_ID
      INTO :CLIENTE_ID, :TOTAL
  DO SUSPEND;
END

-- PostgreSQL
CREATE OR REPLACE FUNCTION vendas_por_cliente(p_ano integer)
RETURNS TABLE (cliente_id integer, total numeric(15,2)) AS $$
BEGIN
  RETURN QUERY
    SELECT v.cliente_id, SUM(v.valor)::numeric(15,2)
    FROM vendas v
    WHERE EXTRACT(YEAR FROM v.data) = p_ano
    GROUP BY v.cliente_id;
END;
$$ LANGUAGE plpgsql;
```
⚠️ As colunas de `RETURNS TABLE` viram variáveis dentro da função. Qualifique as colunas da
tabela (`v.cliente_id`), senão dá erro de referência ambígua. Prefixe parâmetros (`p_ano`).

Selecionável com lógica linha a linha:
```sql
FOR rec IN SELECT ... LOOP
  cliente_id := rec.cliente_id;
  total := rec.total * 1.1;
  RETURN NEXT;          -- equivale ao SUSPEND
END LOOP;
```

**Executável** (sem `SUSPEND`, chamada com `EXECUTE PROCEDURE`):
- PG 11+: `CREATE PROCEDURE ... LANGUAGE plpgsql`, chamada com `CALL nome(...)`.
- Com parâmetros de saída: `INOUT` (PG 14+ aceita `OUT` em procedure) ou uma `FUNCTION` que retorna os valores.
- No Delphi: troque `EXECUTE PROCEDURE X(...)` nas strings SQL. `TFDStoredProc` funciona com os dois.

| PSQL (Firebird) | PL/pgSQL |
|---|---|
| `DECLARE VARIABLE x INTEGER;` | `DECLARE x integer;` (antes do `BEGIN`) |
| `:var` dentro de SQL | `var` (sem dois-pontos) |
| `x = 1;` | `x := 1;` |
| `SELECT ... INTO :x` | `SELECT ... INTO x` |
| `ROW_COUNT` | `GET DIAGNOSTICS n = ROW_COUNT;` |
| `WHEN ANY DO` / `WHEN SQLCODE ... DO` | `EXCEPTION WHEN others THEN` / `WHEN unique_violation THEN` |
| `EXECUTE STATEMENT 'sql'` | `EXECUTE 'sql'` |
| `EXECUTE BLOCK AS ... ` | `DO $$ ... $$;` (sem parâmetros nem retorno) ou uma função |
| `SET TERM ^ ;` | remover (comando do cliente isql) |
| UDF (`DECLARE EXTERNAL FUNCTION`) | função nativa equivalente ou reescrever em PL/pgSQL. ⚠️ pendência |

## SQL (DML e funções)
| Firebird | PostgreSQL |
|---|---|
| `SELECT FIRST 10 SKIP 20 ...` | `SELECT ... LIMIT 10 OFFSET 20` |
| `ROWS 21 TO 30` | `LIMIT 10 OFFSET 20` |
| `FROM RDB$DATABASE` | remover o `FROM` |
| `x CONTAINING 'abc'` (sem diferenciar maiúsculas) | `x ILIKE '%abc%'` |
| `x STARTING WITH 'abc'` | `x LIKE 'abc%'` (diferencia maiúsculas) |
| `'NOW'`, `'TODAY'`, `'TOMORROW'` | `CURRENT_TIMESTAMP`, `CURRENT_DATE`, `CURRENT_DATE + 1` |
| `data + 1` (DATE) | igual para `date`; para `timestamp`: `data + INTERVAL '1 day'` |
| `DATEADD(DAY, n, d)` | `d + n * INTERVAL '1 day'` |
| `DATEDIFF(DAY, a, b)` | `(b::date - a::date)` |
| `EXTRACT(WEEKDAY FROM d)` (0 = domingo) | `EXTRACT(DOW FROM d)` (0 = domingo) |
| `EXTRACT(YEARDAY FROM d)` (**começa em 0**) | `EXTRACT(DOY FROM d) - 1` (o DOY começa em 1) |
| `LIST(x, ',')` | `string_agg(x, ',')` |
| `IIF(c, a, b)` | `CASE WHEN c THEN a ELSE b END` |
| `DECODE(x, 1, 'a', 'b')` | `CASE x WHEN 1 THEN 'a' ELSE 'b' END` |
| `a || b` | igual (NULL propaga) |
| `SUBSTRING(s FROM 2 FOR 3)` | igual |
| `UPDATE OR INSERT INTO t (...) VALUES (...) MATCHING (k)` | `INSERT ... ON CONFLICT (k) DO UPDATE SET ...` (precisa de constraint única em `k`) |
| `MERGE` | `MERGE` (PG 15+), senão `ON CONFLICT` |
| `INSERT ... RETURNING id` | igual |
| `PLAN (...)`, `WITH LOCK` | remover / `SELECT ... FOR UPDATE` |
| `RDB$RELATIONS`, `RDB$FIELDS`... | `information_schema.tables`, `information_schema.columns` |

## Comparação de texto
- `CONTAINING` e collations `PT_BR` do Firebird não diferenciam maiúsculas nem acentos.
  No PG, `=` e `LIKE` **diferenciam**. Opções: `ILIKE`, extensão `unaccent`, ou collation ICU
  não determinística. Decida com o usuário e cubra com teste: isso muda resultado de busca.
